Project Tools

All tools are open source, developed in the SoftwareUnderstanding GitHub organisation, released on PyPI and archived on Zenodo and Software Heritage.

Which one to use? A researcher who wants a check in their own CI, like a unit test, adds rsmetacheck-action. A registry, lab or organisation that wants to watch many repositories without touching them runs rsmetacheck-bot.


rsmetacheck

Core library and command-line tool. It runs SoMEF on one or many repositories (GitHub, GitLab, any branch or tag), applies the 29 detection rules of the catalogue, and writes one JSON-LD report per repository in the EVERSE assessment schema. Each finding carries its evidence (file and value), a link to the catalogue entry and a suggestion built from the repository itself, e.g. "set version to 1.2.0, the latest release". It can also generate a codemeta.json from SoMEF output.

rsmetacheck-action

GitHub Action for developers. It runs rsmetacheck on each push or pull request, shows the findings as a Markdown summary and as inline annotations on the pull request diff, and fails the step when it finds issues. The rsmetacheck documentation describes an equivalent GitLab CI/CD job.

v0.3.6, versioned with the core package

GitHub Marketplace · Source code

rsmetacheck-bot

Bot for whoever oversees a set of repositories. It takes a list of repositories, runs rsmetacheck, and opens, updates or closes one issue per repository. It remembers the last analysed commit, the issue it opened and any opt-out, so maintainers get one issue per repository, not one per run. It supports GitHub, GitLab.com and self-hosted GitLab, an unsubscribe command and a dry-run mode, and proposes a ready-to-use codemeta.json when a repository has none. It runs on the ESCAPE OSSR and on the OEG-UPM organisation.

rsmetacheck-dashboard

Static website regenerated after each bot run. It lists the monitored repositories, their latest findings, links to the bot issues and the history of past runs.

Auto CodeMeta generator

Web application to create a codemeta.json file. It extends the CodeMeta generator maintained with Software Heritage: paste a GitHub, GitLab, Codeberg or Bitbucket URL and SoMEF pre-fills the form (name, description, dates, SPDX license, keywords, authors, CI, issue tracker, languages). It produces CodeMeta 2.0 or 3.0 and validates the result.

SoMEF

Software Metadata Extraction Framework, maintained by UPM. It extracts metadata from README files, package manifests and platform APIs, and underpins every tool above. CodeMetaSoft drove releases 0.9.9 to 0.10.3: GitLab support, SPDX license export, release, version and commit ID extraction, and CodeMeta export fixes. Running rsmetacheck at scale exposed extraction bugs, and each fix reduced false positives in rsmetacheck.

Data and Resources

Metadata pitfalls catalogue

29 metadata issues (19 pitfalls, 10 warnings) in six themes: structure and schema, licensing and attribution, versioning and synchronisation, citation and provenance, documentation, automation and quality control. Each entry has a definition, a real example, suggested fixes and a persistent identifier, e.g. https://w3id.org/rsmetacheck/catalog/#P001. Open to community contributions.
